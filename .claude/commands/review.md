---
description: הסבר פשוט של בקשת מיזוג (PR) לפני שמאשרים אותה
argument-hint: "[מספר PR]"
---

המשתמש לא מתכנת, והוא צריך להחליט אם לאשר בקשת מיזוג. התפקיד שלך הוא להסביר לו בעברית פשוטה מה היא עושה ומה הסיכון. אל תשנה קוד ואל תמזג.

1. אם לא קיבלת מספר PR (כאן: "$ARGUMENTS"), הרץ `gh pr list` והצג כל PR פתוח בשורה אחת. אם יש רק אחד, בדוק אותו. אם יש כמה, שאל איזה.
2. קרא אותו: `gh pr view <n>`, `gh pr diff <n>`, `gh pr checks <n>`.
3. ענה בקצרה, במבנה הזה:
   - **מה זה משנה במשחק:** מה השחקן ירגיש.
   - **הבדיקה האוטומטית:** עברה, נכשלה או עוד רצה. אם נכשלה, מה נכשל במילים פשוטות.
   - **עמידה בכללים של CLAUDE.md:** מכניקה בקובץ משלה עם המספרים באובייקט אחד, בלי `import` ו-`export`, קוד הצבעים (כתום לחרב, תכלת לקשת, זהב לשלל), כל טקסט חדש ב-`js/lang.js` בעברית ובאנגלית (בלי טקסט בתוך קוד המשחק), ורשומה ביומן. כתוב רק מה שחסר או נשבר.
   - **סיכונים:** כל קובץ שנמחק, בשמו. שינויים בקבצים שכל המשחק נשען עליהם (`update.js`, `render.js`, `combat.js`, `state.js`). שינויים גדולים שלא קשורים לכותרת.
   - **איך לנסות לפני שמאשרים:** `gh pr checkout <n>`, לפתוח את `index.html`, מה בדיוק לנסות, ובסוף `git switch -` כדי לחזור לענף הקודם.
   - **ההמלצה שלי:** לאשר או לבקש תיקונים, ולמה.
4. מיזוג רק אם המשתמש אומר במפורש למזג, ורק כשהבדיקה ירוקה.
